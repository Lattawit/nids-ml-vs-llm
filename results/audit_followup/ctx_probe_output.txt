1-shot: identical count at both settings -> NOT truncated (2619 tokens comfortably fits in 4096).

3-shot (seed 303): TRUNCATED. True prompt is 6,524 tokens; at the default 4096-token context only 2,050
tokens (31.4%) are actually evaluated -- 4,474 tokens (68.6% of the prompt) are silently dropped before the
model ever sees them. This happened in every actual v3/v4 3-shot-ablation run (none set num_ctx), and by
construction of llama.cpp/Ollama's over-length-prompt handling (server log shows n_keep=4, i.e. only the
first 4 tokens are protected), truncation drops content from the START of the prompt and keeps the tail --
so the "knowledge" class-definitions block and the EARLIER reference examples (Benign/Bot/Brute
Force/DoS-DDoS/Infiltration, in that fixed sorted-by-label-id order -- see llm_classification_few_shot_v4
_3shot_ablation.py:257) are the first content discarded, while the LAST examples in the block (PortScan,
Web Attack -- label ids 5 and 6, positioned immediately before "Traffic to Classify") and the traffic row
itself survive intact.

This gives a mechanistic, non-speculative explanation for the "collapse" pattern already reported (Bot/
Brute Force/DoS-DDoS/Infiltration -> 0% recall in every 3-shot run, predictions concentrating on PortScan/
Web Attack): the model was answering with a truncated prompt that had structurally lost the class
definitions and reference examples for exactly the four classes that collapsed, while PortScan and Web
Attack's examples (being last, right before the row to classify) survived. Corroboration: a same-row probe
at default settings and num_predict=60 (not 1) in the prior audit session returned raw text "Web Attack"
for this same true-Benign row -- consistent with the model latching onto whichever example survived nearest
the end of the truncated prompt, not the correct class.

This reframes CLAUDE.md's "Likely a 'lost in the middle' prompt-length effect rather than a bug" (Sep 12
entry): it is not a vague attention-distance effect, it is literal, structural context-window truncation
caused by never setting num_ctx while the true 3-shot prompt (~6.5k tokens) exceeds the server's
auto-selected 4096-token default.
