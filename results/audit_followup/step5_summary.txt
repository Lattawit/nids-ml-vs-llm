CONCLUSION: effect of removing Protocol from the LLM prompt is SMALL and DIVERGES BY MODEL SIZE --
slightly helps 7B (+0.72pp acc, +0.011 macro F1), slightly hurts 14B (-1.28pp acc, -0.031 macro F1). For
14B, removing Protocol shifts predictions away from Benign/Infiltration toward PortScan/Brute
Force/DoS-DDoS; PortScan recall stays perfect (1.00) but its F1 drops (0.743->0.665) because precision
falls -- more non-PortScan rows get called PortScan once the Protocol shortcut is gone. This suggests
Protocol is not PURELY a spurious origin-fingerprint for the LLM the way Task 2 showed it to be for the
ML models (RF/XGBoost/MLP retrain showed negligible effect there) -- 14B appears to have been using it as
a partially genuine (if leakage-correlated) discriminating signal, plausibly because protocol choice
(TCP/UDP/ICMP) does have some real correlation with attack type independent of dataset origin.
