# Machine Learning vs. Prompt-Engineered LLMs for Multiclass Network Intrusion Detection

Code, prompts, feature definitions, and result files for the paper

> L. Sirisawat, T. Thesniyom, and K. Yongsiriwit, "Comparing Machine Learning and
> Prompt-Engineered Large Language Models for Multiclass Network Intrusion Detection,"
> ICA-SYMP 2027.

The study compares Random Forest, XGBoost, and an MLP with Qwen2.5:7B / Qwen2.5:14B
(zero-shot, few-shot, three-example, and dynamic few-shot prompting via Ollama) on a
merged CIC-IDS2017 + CSE-CIC-IDS2018 dataset. It also documents and corrects two
leakage problems in the naive merge: a dataset-origin fingerprint caused by
mismatched column names, and exact duplicates shared between the train and test
splits.

The raw datasets are **not** redistributed. Download them from the Canadian Institute
for Cybersecurity:
- CIC-IDS2017: https://www.unb.ca/cic/datasets/ids-2017.html
- CSE-CIC-IDS2018: https://www.unb.ca/cic/datasets/ids-2018.html

## Environment

- Python 3.14 (tested with 3.14.4); `pip install -r requirements.txt`
- Ollama **v0.40.13**, models (default Q4_K_M builds):
  - `qwen2.5:7b`, digest `845dbda0ea48ed749caafd9e6037047aa19acfcfd82e704d7ca97d631a0b697e`
  - `qwen2.5:14B`, digest `7cdf5a0187d5c58cc5d369b255592f7841d1c4696d45a8c8a9489440385b22f6`
- Decoding: temperature 0, `num_predict` 60; `num_ctx` left at Ollama's default (4096) except the 3-example prompt (8192).
- Hardware used: Intel i5-14400F, 32 GB RAM, RTX 4060 8 GB (the 14B model is partly offloaded to CPU). The 5-fold CV needs about 10 GB of RAM.
- `research/ollama_host.py` finds the Ollama server: the `OLLAMA_HOST` environment variable, then `localhost`, then the WSL2 gateway IP (for Ollama running on the Windows host).

Even at temperature 0, individual LLM predictions are not bit-reproducible across runs (accuracy is; see the paper). The per-row responses used for the paper are in `results/revision/*/llm/*.jsonl`.

## Reproducing

Every script is run from the repository root with no arguments: `python research/<script>.py`. Settings are constants in each script's `CONFIG` block.

### 1. Data pipeline (Table I)

Place the raw CSVs under `datasets/CIC-IDS2017/` and `datasets/CSE-CIC-IDS2018/`.

| Step | Script | Output |
|---|---|---|
| Clean each raw file (run twice; edit `DATASET_FOLDER`) | `clean_all_files.py` | `cleaned/<dataset>/` |
| Map labels to 7 classes | `label_mapping.py` | `mapped/<dataset>/` |
| Merge both datasets, drop Heartbleed | `merge_datasets.py` | `results/final_merged_dataset.csv` (18,303,717 rows) |
| Coalesce 2017/2018 column pairs, drop constant and identifier columns | `coalesce_features.py` | `results/final_merged_dataset_coalesced.csv` (70 features) |
| Duplicate and leakage audit (21.1% duplicates; 16–49% train/test overlap without dedup) | `train_test_split_pipeline_v3.py`, then `check_duplicates_v3.py` | `results/duplicate_check_v3/` |
| Remove exact duplicates (keep first) | `deduplicate_dataset_v4.py` | `results/final_merged_dataset_deduped.csv` (14,439,966 rows), `results/dedup_v4/dedup_report.csv` |
| Stratified 70:30 split | `train_test_split_pipeline_v4.py` | `results/split_data_v4/` |
| Confirm no train/test duplicates | `check_cross_split_duplicates_v4.py` | `results/duplicate_check_v4/` |
| Undersample + SMOTE (training split only) | `balance_dataset_v4.py` | `results/split_data_v4/X_train_smote.csv`, `training_balancing_report.csv` |

### 3. Camera-ready experiments (Tables II–V, Fig. 3)

Run in this order (`research/revision/`):

| Step | Script | Paper |
|---|---|---|
| Draw 5 disjoint 700-row subsets (seed 42 = original) + few-shot examples | `setup_subsets.py`, then `check_prompts_v4.py` | Sec. III-G |
| Real vs. synthetic share per class | `e3_real_vs_synthetic.py` | Table I |
| 22-feature models | `e2_train_models_22feat.py` | Table II |
| No-SMOTE, class-weighted models | `e5_train_nosmote_weighted.py` | Sec. IV-A |
| ML on the 5 subsets / full held-out set | `eval_ml_on_subsets.py`, `eval_ml_heldout.py` | Tables II–IV |
| LLM zero-/few-shot on the 5 subsets (resumable) | `run_llm_jobs.py` | Tables II, V |
| Dynamic few-shot retrieval + 1-NN / k-NN baselines | `e4_retrieve_examples.py`, then `run_e4_jobs.py` | Tables II, V |
| 3 examples per class on the 5 subsets | `e8_threeshot_examples.py`, then `run_e8_jobs.py` | Table II |
| Means, SDs, per-class F1, McNemar | `aggregate_results.py` (→ `results/revision/summary/`) | Tables II, IV, V |
| Pooled confusion matrix | `fig3_confusion_pooled.py` | Fig. 3 |
| 5-fold CV | `e6_cv5_ml.py` | Table III |
| Train CSE-CIC-IDS2018 → test CIC-IDS2017 | `e7_source_separated.py` | Sec. IV-D |

LLM runners append each response to a JSONL file and skip finished rows on restart. Run only one LLM job at a time; concurrent jobs distort the timings.

## Not included

- The raw, cleaned, merged, and split data (regenerated by the pipeline) and trained model files.
- Any file containing CIC dataset rows: the 700-row evaluation subsets (`create_llm_subset_v4.py`, `setup_subsets.py`), the few-shot example rows (`setup_subsets.py`), the per-flow retrieved examples (`e4_retrieve_examples.py`), the 3-example prompt blocks (`e8_threeshot_examples.py`), and a 140-row audit sample. Running the scripts on the downloaded datasets regenerates them; `setup_subsets.py` asserts that the seed-42 subset is byte-identical to the original.
- The earlier v2 pipeline, which produced the uncorrected comparison number quoted in the paper's Discussion (96.14% Random Forest accuracy before the fixes).
- The scripts for the ML half of the Protocol-removal check and for the Benign/Infiltration identical-feature count; their outputs are in `results/audit_followup/`.

Some comments in the scripts refer to project notes (`CLAUDE.md`) from the development repository; they are not needed to run anything.
